### S02242601 Context-scoped EventSplitter wiring

Context exposes an eventSplitterFactory, but the event pipeline always uses a singleton EventSplitter
(SplitEvent), so context-specific splitting never actually applies. This creates a design mismatch between
configuration and execution, and makes it impossible to tailor event decomposition per context (which is
critical for multi-op codebases with different event semantics).

- Thread the Context-selected EventSplitter into transaction/event processing (e.g., store it on Tr or
  pass it via EventLogic) and use it in SplitEvent/ReceiveEvent.
- Define precedence when multiple contexts match (which splitter wins, or whether splitters compose),
  and make the choice explicit in configuration and documentation.
- Add a small contract test that proves per-context splitter selection is honored.
