### S02222612 Introduce immutable configuration snapshots

Configuration state is currently kept in mutable builders and registries that are cleared or repurposed at
finalization time. Introduce an immutable ConfigSnapshot that is built once at finalizeConfiguration() and
used by runtime resolution/evaluation. This separates configuration from execution, improves thread-safety,
opens the door for future hot-reload/versioned configs, and centralizes indexing/ordering decisions.

- Add ConfigSnapshot that owns resolved contexts, transactions, and indexes in a read-only form.
- Update ConfigurationLogic/FinalizeConfiguration to build and publish the snapshot and reject further
  configuration mutations with explicit errors.
- Route runtime lookups (context resolution, indexes) through the snapshot instead of builder state.
- Add tests asserting snapshot immutability and that post-finalize config changes do not affect runtime.
- Document the configuration/execution boundary and snapshot behavior in Readme.md.
