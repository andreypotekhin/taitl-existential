### S03102602 Specify context matching and rule ordering semantics

Specification describes that matching and parent contexts execute before child contexts, but it does not define
the ordering when multiple matching contexts exist (e.g., parent chain plus multiple wildcards) or how rule
ordering composes across those sources. This leaves user-visible behavior ambiguous.

- Define deterministic ordering among multiple matching contexts (parent depth vs wildcard specificity vs exact match).
- Specify tie-breaking for same-depth contexts, including registration order vs lexical order.
- Clarify how rule ordering composes across contexts and custom transaction rules (e.g., parent context rules first,
  wildcard rules next, then concrete context, then transaction instance overrides).
- Document whether wildcard contexts are evaluated per stage in the same order, and how this impacts intent handling.
