### S02222612 Context-scoped event splitting pipeline

Context exposes eventSplitterFactory(), but ReceiveEvent/SplitEvent always use a singleton EventSplitter. This
is a design mismatch that disables per-context customization and makes event splitting global in a place that
should be context-aware. Redesign the event processing pipeline to resolve an EventSplitter per matching
Context/Transaction, split events with that instance, then feed the results into immediate handlers and
indexing with deterministic ordering.

- Resolve matching contexts for a Tr and obtain their eventSplitterFactory instances.
- Split each incoming event using the context-specific splitter before handler execution and indexing.
- Define a deterministic merge order (parent before child, wildcard before specific) and de-duplicate
  emitted events in a context-aware way.
- Add tests proving custom EventSplitter is used for a context and ordering is preserved.
