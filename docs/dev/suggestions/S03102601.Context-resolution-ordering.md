### S03102601 Context resolution and ordering pipeline

Context resolution currently mixes set-based storage (SetMap), TODOs for wildcard retrieval, and per-call matching
loops. This leaves matching order and tie-breaking implicit and risks non-deterministic rule evaluation when multiple
contexts apply. Introduce an explicit context resolution pipeline that produces an ordered, immutable view of contexts
for an op, with stable ordering and cached lookup.

- Build a ResolvedContextSet per op that includes direct, parent, and wildcard contexts in deterministic order.
- Define a stable ordering strategy (e.g., exact match, then parents by depth, then wildcards by specificity, then
  registration order) and enforce it in a single place.
- Cache resolved context lists in ConfigurationLogic/ConfigRegistry to avoid repeated MatchParentName scans.
- Store both the ordered list and a fast lookup (e.g., map by context key) for downstream indexing.
- Make wildcard inclusion explicit (no TODO), with a dedicated component responsible for wildcard discovery.
