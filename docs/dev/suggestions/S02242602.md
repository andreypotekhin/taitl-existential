### S02242602 Specify intent semantics and access decision flow

The spec introduces Intents and access rules, but the "Configuring Intents" section is empty and the
workflow does not define how intents are evaluated, how allow/deny conflicts are resolved, or what happens
when no intent rules exist. This leaves a core access-control feature underspecified and forces readers to
infer behavior from code.

- Define intent evaluation order (context vs transaction, parent vs child) and conflict resolution rules.
- Specify defaults: what happens when no intents exist for a given access event.
- Document what access failures look like (exception type, report format, and where to find remediation).
