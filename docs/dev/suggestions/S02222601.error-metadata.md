### S02222601 Error metadata for public exceptions

Introduce a small, consistent error metadata surface for public exceptions (error id + troubleshooting link), so
end users can map failures to specific docs quickly and log parsing remains stable. Start with
com.taitl.existential.exceptions and use a helper (e.g., ExceptionMessage) to append metadata without repeating
string concatenation in each call site.

- Define a compact error id catalog in /docs (or a dedicated constants class).
- Update public exception factories to include error id + troubleshooting link.
- Add a troubleshooting section per error id and keep links stable.
