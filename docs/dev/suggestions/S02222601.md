### S02222601 Stage-partitioned rule storage and evaluation

Context and Transaction store all rules in a single `List<Evs<?>>` while the spec defines explicit stages
(Precondition, Runtime, Validation) and the exceptions already model a stage. This conflates ordering and
execution semantics, makes it unclear which stage a rule targets, and forces runtime logic to infer intent.
Introduce an explicit stage model and partitioned rule storage so evaluation order and stage boundaries are
deterministic and self-documenting.

- Add a `Stage` enum (Precondition, Runtime, Validation) and a `StageRules` container that owns per-stage
  `Instructions` and `List<Evs<?>>`.
- Update `Context` and `Transaction` to add rules into the correct stage bucket, with a clear default stage
  in the API (and a strict opt-in for immediate rules).
- Wire evaluation logic to consume stage-specific instructions so runtime/validation phases no longer scan
  a mixed list.
