### S02222602 Specify context matching precedence and event identity

The specification defines parent contexts, matching wildcard contexts, and direct contexts, but it does not
state the exact precedence when multiple kinds match the same operation. It also says immediately evaluated
rules are out of order without defining what counts as immediate or how that impacts ordering. Clarify the
matching and ordering semantics to make evaluation deterministic and allow implementers to reason about
behavior without reading source code.

- Define the canonical context resolution order (e.g. parent chain first, then wildcard matches by specificity,
  then direct context) and how duplicate rules across contexts are handled.
- Define event identity and de-duplication rules (what makes two events “equal,” and which stages honor de-dup).
- Specify how immediate rules interleave with staged evaluation, including whether they can observe partial
  state that staged rules have not yet processed.
