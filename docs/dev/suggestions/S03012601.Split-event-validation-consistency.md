### S03012601 Split-event validation consistency

`EventSplitter` and `SplitByEventType` mix direct `IllegalArgumentException` construction with `Args.sane`/`Args.check`
for parameter validation, producing uneven error phrasing and duplicated literals. Centralize validation by routing
all null checks through `Args.sane` (or shared helper methods) so messaging and behavior remain consistent across the
split pipeline.

- Replace direct null checks in `SplitByEventType` with `Args.sane`/`Args.check`.
- Add a small helper (package-private) for event/null validation to reuse in `EventSplitter`/`SplitByEventType`.
- Update tests asserting on message wording after standardizing the phrasing.
