### S02222613 Define event identity and de-dup semantics in specification

Specification states that multiple equal events are treated as one, but it never defines equality for
Event/Mutation/Transition (object identity vs equals vs key), nor how before/after pairs compare. This leaves
core behavior ambiguous and risks mismatches between EventKey/RuntimeKey indexing and user expectations.
Clarify the event identity rules and de-duplication semantics in Specification.md so evaluation order and
validation behavior are deterministic.

- Add a specification subsection defining event identity for single-entity events and bi-events.
- Specify how equality treats before/after pairs (t0/t1) and null cases, and how it maps to EventKey.
- State how duplicates are merged across runtime and validation stages.
- Add spec tests that cover de-duplication rules and ordering.
