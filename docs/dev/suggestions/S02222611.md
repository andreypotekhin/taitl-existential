### S02222601 ContextBuilder should attach configured contexts

ContextBuilder.build() creates a new Context instance and configures it, but never attaches it to the parent
ConfigBuilder. This can silently drop configured rules or transaction factories because ConfigBuilder.build() only
uses its own contexts list. Suggest binding the built context to the parent (either by adding it via
ConfigBuilder.context(Context) or by locating the existing context for the op and applying rule factories to it).

- Decide whether to attach new contexts or mutate existing contexts created by BuildContexts.
- Update ContextBuilder.build() to ensure configured rules end up in the ConfigBuilder contexts list.
- Add a regression test that configured rules are present when a transaction begins.
