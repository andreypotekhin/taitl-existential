### S03121601 Ex.memo

Currently in SplitEventType, the parameters for BiEvents
are chosen somewhat arbitrarily, e.g. same entity instance
is used for both before- and after- states (ex: new Transit<>(entity, entity))

We want to take out hacky guesswork from this process,
by storing the initial value of the object (memento pattern)
prior to evaluating other events, and using that value
as t0 (before-) parameter when creating ByEvents.

Proposing to add memo() methods to Tr class for storing
'before' states of various classes. The objects can be
stored in a map by object identity for the duration
of transaction.

Ex:
tr.memo(myObject.clone(), TypeKey<MyType>(){})
tr.memo(myObject.clone(), MyType.class)
Ex.memo(myObject.clone(), TypeKey<MyType>(){}, String tranID)
Ex.memo(myObject.clone(), MyType.class, String tranID)

One potential issue is the user will often forget to clone
its object, which will lead for same object used as
before- and after- state.
We need to think of ways to prevent this.
