### S03102601 Transaction lifecycle state

Add a small transaction lifecycle state machine to make phase transitions explicit (active, checkpointed, closed)
and expose a `status()`/`isActive()` read-only accessor on `Tr` so callers can guard event emission proactively.
This would centralize lifecycle validation, improve error messages for invalid transitions (commit after rollback,
events after checkpoint), and make test intent clearer.
- Introduce a `TransactionStatus` enum and store it on `Tr`.
- Validate transitions inside `TransactionLogic` and surface consistent `ExistentialException` messages.
- Add spec coverage for invalid transitions and for status exposure.
