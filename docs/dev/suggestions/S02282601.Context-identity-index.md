### S02282601 Context identity index in ConfigBuilder

ConfigBuilder tracks contexts in a List and guards duplicates via `contexts.contains(context)`, which only
catches the same instance. Multiple Context objects with the same path can be added silently, leading to
nondeterministic ordering or duplicate rule execution when configuration is assembled. Promote context
identity to a first-class concept (by name/path) so duplicates are detected deterministically and the merge
behavior is explicit.

- Replace the List with a LinkedHashMap keyed by normalized ContextKey (or similar), preserving order.
- Decide the duplicate policy: reject with a clear error, or merge into the existing context in a defined order.
- Add a regression test that two contexts with the same path cannot be registered silently.
