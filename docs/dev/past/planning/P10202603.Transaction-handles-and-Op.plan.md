This ExecPlan records the selected Sprint 01 implementation. A caller can report events by string ID while retaining the
`Tr` returned by `begin` for commit, checkpoint, and rollback. A rejected commit removes the transaction from active
string-ID lookup but leaves the caller-held handle available for explicit rollback. Annotated operations use one local
handle per invocation. The Night City acceptance flow demonstrates cat creation and relocation with collection-backed
dwelling checks.

## Decision log

**Lifecycle identity.** `begin(String)` returns the handle used for commit, checkpoint, and rollback. Remove those String-ID
lifecycle variants from the public Ex and Existential facades. Preserve String-ID event, access, and memo APIs and the
active registry lookup those APIs require.

**Failed commit.** A commit failure removes the handle from the active registry immediately. The handle becomes
rollback-only: it cannot accept more events, checkpoints, or another commit, but a caller may explicitly call rollback.
Rollback callbacks run only on that explicit call. Rollback disposes transaction-local state in a `finally` path even if
a rollback callback fails. If the caller abandons the handle, the registry no longer retains it; normal Java reachability
allows the handle and its data to be reclaimed. There is no secondary pending registry and no automatic rollback callback.

**Annotated operations.** Use one execution-only around advice with a local `Tr` for each invocation. Return the method
result after successful commit. On a method or commit throwable, attempt rollback on that same handle, attach a distinct
rollback throwable as suppressed, and rethrow the original. Keep `Op.opKey()` unchanged.

**Validation reports.** Allocate each report inside its validation run. A failed validation attempt must not cause an
otherwise valid later transaction to fail with stale violations.

**Night City workflow.** Use `/night-city/cats/save` for create and relocation acceptance. New cats are black; each
created or relocated cat must have a caller-supplied dwelling at its destination; relocation preserves color. The tests
exercise valid and rejected paths with explicit transaction handles.

## Implementation notes

The public facades live in `src/main/java/com/taitl/existential/Ex.java` and `Existential.java`. `ExistentialTransactions`
and `TransactionLogic` route handles; `TrRegistry` owns the active String-ID lookup; `ConcreteTr` owns mutable event,
memo, stage, and rollback-only state. `DisposeTran` removes an entry if present and closes the handle. Removal is
idempotent because a failed commit already detached its handle before explicit rollback.

`OpAspect` is compiled and woven by the AspectJ Maven plugin declared in `pom.xml`. The overlap acceptance fixture lives
in `src/test/java/com/taitl/specs/library_usage/UserCanUseAnnotatedOperations.java`; Maven output should show its
annotated methods advised by `OpAspect`. The Night City walkthrough and failed-commit recovery cases live in
`UserCanCreateAndRelocateCats.java` and `UserCanConfigureEntities.java`.

Surefire previously replaced JaCoCo's prepared `argLine` with only `--enable-preview`, so coverage data was missing.
Ordinary Surefire now composes the prepared JaCoCo argument with the preview option. The benchmark profile remains
uninstrumented so its timings can be compared to the pre-change samples.

registry to retain failed handles; the caller's handle is the explicit recovery path.
