## Context and Orientation

The root `pom.xml` is the library artifact. `examples/night_city/pom.xml` is an independent consumer of the installed
library, while `reactor/pom.xml` orders both projects for a combined build. Configuration is finalized on first
transaction start by `FinalizeConfiguration`; configured state must mean the configuration build completed.

## Concrete Steps

From the repository root:

    mvn clean install
    mvn -f examples/night_city/pom.xml clean verify exec:java
    mvn -f reactor/pom.xml clean install
    mvn -f examples/night_city/pom.xml org.apache.maven.plugins:maven-dependency-plugin:3.3.0:tree

Run the consumer workflow benchmark three separate times with 50 warmups and 250 measured workflows at each source
size. Verify `target/existential-0.0.1.jar` and root `existential.jar` contain no Night City/test classes or JUnit
classes. Installation writes to the user's local Maven repository; rerun the reactor command with approved repository
access if the workspace sandbox blocks that write.

## Idempotence and Recovery

All clean Maven commands can be repeated. Root install refreshes the stable local artifact before standalone consumer
verification. If artifact inspection or a consumer run fails after edits, rerun root installation before interpreting
consumer results. Failed configuration finalization can be retried using the existing builder and transaction start.
