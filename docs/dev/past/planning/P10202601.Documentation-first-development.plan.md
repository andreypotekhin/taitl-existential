## Context and Orientation

The root Maven project produces `com.taitl:existential:0.0.1-SNAPSHOT`. Java sources live under `src/main/java`,
unit and specification tests under `src/test/java`, and Night City currently under
`src/main/java/com/taitl/ex/examples/night_city`. `docs/dev/Specification.md` contains the existing behavior claims;
leading plus signs record previous completion assertions. `docs/dev/project/Roadmap.md` assigns release scope.
`pom.xml` runs formatting automatically and assembles a root-level `existential.jar` during packaging.

Finally create the performance guide, record template, and custom-transaction topic history under

## Milestones

Documentation foundation is complete when claims have unique identifiers, old specification links still navigate,
and the agent process permits both exploratory discussion and user-outcome-driven work selection.

Release planning is complete when each roadmap item has an epic, sprint, specification reference, evidence or gap,
and explicit dependency. Each release ends with a feature-free hardening sprint and records its exit criteria.

Example extraction is complete when a clean Maven build runs existing tests and neither library JAR contains
`com/taitl/ex/examples/night_city/`. Performance accumulation is complete when the guide and topic summary point to
three actual samples with enough context to repeat the measurement.

## Concrete Steps

Work from the repository root. Read `Agents.md`, `docs/dev/Style.md`, and `docs/dev/auto/Plans.md` first.
After writing the documentation and moving the sources, run:

    mvn clean install
    mvn -q -Pbenchmarks -Dbenchmark.warmup.iterations=5000 -Dbenchmark.measure.iterations=50000 test

Repeat the benchmark command three times as separate invocations. Inspect `target/surefire-reports` for actual totals.
Inspect the normal JAR under `target` and the assembled root `existential.jar` with `jar tf`; neither should contain
Night City classes. Validate relative Markdown links and anchors, requirement identifiers, and preserved claim text.

## Validation and Acceptance

The full build must succeed with tests, including existing specification tests that import Night City. The three

## Idempotence and Recovery

The migration moves sources rather than duplicating them. If rerunning a step, inspect its target before moving it.
Use `mvn clean` to eliminate stale example classes. Preserve the user's Usage.md edits and unrelated repository work;
do not use a blanket checkout/reset. If dependency resolution fails, retry the pinned plugin download without changing
its version or disabling checks. Retain any incomplete evidence as incomplete rather than recording success.
