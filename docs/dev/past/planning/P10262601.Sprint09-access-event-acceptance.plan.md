## Surprises & Discoveries

Read-and-lock expands to read even when elementary-to-compound expansion is disabled: it is a compound-to-elementary
selection. Write does not imply a create/update event. Access does not imply read/read-and-lock/write. General On and
entity expressions can observe all four; there is no public OnAccess shortcut. These reports describe caller actions;
the library performs no database access or locking.

General On declarations index under Event, but ResolveSelectionInput omitted that route and intent grouping never
looked it up. Initial acceptance reproduced skipped general constraints/effects and bypassed general intents. The
correction adds a selection family without inventing a new event or recording another runtime entity.

Matching read, lock, and general intents through separate groups also requires merging them back into declaration
order. OrderApplicableIntents uses EventField's cached shared selection, then the active handle's local declaration
order. Scope/type matching and explicit predicate disjunction remain unchanged. Explicit rollback completes the
handle; another rollback is rejected as closed, while repeated close is safe.
