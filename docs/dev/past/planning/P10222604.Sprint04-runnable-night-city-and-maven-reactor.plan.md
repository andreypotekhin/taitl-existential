# Deliver Sprint 04: Runnable Night City and Maven Reactor

This plan delivers Night City as a runnable example and independently verified consumer of the library. It preserves
the existing root library layout and commands while adding a separate reactor for combined builds.

## Purpose / Big Picture

Users can build Night City against the installed public library artifact, run a noninteractive success/rejection/recovery
story, and verify the same workflow from an independent consumer project. A separate reactor orders the existing root
library and Night City modules without making the library depend on the example artifact.

## Surprises & Discoveries

- Surefire 2.22.2 with JUnit 5.14.3 reported zero discovered consumer tests because the platform engine and launcher
  APIs were misaligned. The independent POM uses JUnit 5.8.2 plus its matching launcher; standalone and reactor builds
  then execute the acceptance test.
- The configured exec plugin version was not locally available in the restricted Maven cache. The consumer uses the
  locally available 3.1.0 release, and its configured main class can be overridden for the separate benchmark.
- Installing within the reactor required permission to write Maven artifacts outside the workspace. The user-requested
  build completed with that access.
- Root test execution exposed tests that opened transactions without closing them under the new graceful-shutdown
  default. Those tests now close their handles explicitly.

## Decision Log

  the optional build aggregator in `reactor/`. The root library remains a direct module, not a child that inherits from
  the reactor. Rationale: preserve root commands and coordinates, prove independent artifact consumption, and avoid a

## Context and Orientation

The root [pom.xml](../../../../pom.xml) owns `com.taitl:existential:0.0.1-SNAPSHOT` and adds Night City source files as shared
test sources. `examples/night_city/pom.xml` depends on that installed coordinate and does not inherit the reactor. The
aggregator `reactor/pom.xml` lists the root project before Night City. `NightCityStory` calls the existing
`ConfigureCats` rules through public transaction handles; `NightCityStoryTest` runs the exact same story as a consumer
acceptance test.

The runnable story demonstrates one rejected non-black cat followed by explicit rollback, a fresh successful creation,
and a color-preserving relocation to a dwelling. It closes every handle and its library instance. The consumer benchmark
measures complete success, rejection/rollback, fresh recovery, and 16 repeated reads over source sizes; setup and cleanup
are outside timed intervals.

## Plan of Work

Keep artifact coordinates unchanged. Do not add external publication or a library dependency on Night City. Ensure the
consumer compiles with its own source tree and resolves the installed library. Use existing `ConfigureCats` rules and
public `Tr` APIs. Add a separate reactor rather than changing the root project into an aggregator.

Keep performance setup outside transaction timings. Record environment, exact command, source identity, workloads,
three independent samples, median/range, limitations, and deterministic cleanup. Establish baseline evidence without a
numerical regression threshold.

## Idempotence and Recovery

Rerunning the clean builds removes prior module outputs. Root install refreshes the Maven local artifact; the standalone
consumer verifies the dependency without reactor class directories. If standalone verification follows source changes,
install the root library again before accepting results. Reactor builds provide an alternative combined verification.
Any failed benchmark operation fails the process; transaction and library `finally`/`close` paths release resources.

## Interfaces and Dependencies

No public library API or new runtime dependency is introduced. The consumer adds only JUnit Jupiter and its matching
JUnit Platform launcher in test scope. The reactor POM is build orchestration only and is not a parent of either module.
