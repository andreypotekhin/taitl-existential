### T10212601. Quantifier rules are skipped by event dispatch

Completed 2026-10-21. Shared expression dispatch now selects fluent All/Exists rules for reported entity/access events,
using transition after-values and deletion before-values. Rules execute once per matched declaration/encountered event,
in declaration order, through both static and transaction-local caches. Reflected multi-argument generic keys now use
the same comma separators as runtime expansion. ConfigureCats uses fluent rules without the event-bound workaround.
See the [completed plan](../planning/P10212601.Quantifier-dispatch.plan.md),
[acceptance tests](../../../../src/test/java/com/taitl/specs/library_usage/UserCanValidateEntityQuantifiers.java), and
[performance record](../../performance/runs/20261021T223641Z.QuantifierDispatch.md).
Final `mvn clean install`: 423 tests, zero failures/errors, three existing disabled report tests; coverage/checks passed.
The investigation below records the pre-fix failure and rationale.

Investigation on 2026-10-21 confirmed that fluent `invariant(Cat.class).exists(map, description)` and `.all(predicate,
description)` rules are registered but never selected for a reported create event. This is a dispatch defect, not an
intended semantic difference between fluent quantifiers and event-bound predicates. The current cat workflow's
`create(new Exists<>(map), description)` workaround does execute; its separate `.all(...)` location rule does not.

#### Reproduction and evidence

Configure a context with just the following rule, report a cat absent from the map, then commit:

    ex.configure().context("/probe/exists").invariant(Cat.class)
        .exists(Map.<Cat, String>of(), "Every cat must have a dwelling");
    Tr tr = ex.begin("/probe/exists");
    tr.create(new Cat("Black", "Rooftop"));
    tr.commit();

Expected: commit rejects the missing key. Actual: commit succeeds without evaluating the rule.

An isolated four-case JUnit probe ran with `mvn -Dtest=QuantifierDispatchInvestigationTest test` and confirmed:

- Direct `Exists.test(cat)` returns false for a missing key; `Exists.evaluate(cat)` throws `PredicateFailure`.
- A fluent map quantifier whose predicate increments a counter and returns false allows commit; the counter stays zero.
- A fluent `all` predicate that increments a counter and returns false also allows commit; its counter stays zero.
- The same missing-key quantifier bound through `.create(new Exists<>(map), description)` rejects commit.

The probe characterized the defect and was removed from test sources rather than making the defect a passing regression
requirement. Its source and execution log are retained for this local investigation at
`/tmp/QuantifierDispatchInvestigationTest.java` and `/tmp/taitl-quantifier-dispatch-investigation.log`.

After removing the probe, `mvn clean install` passed: 395 tests, zero failures/errors, three existing disabled
validation-report tests, and passing JaCoCo checks. This verifies the investigation left the runtime unchanged;
it does not establish correct quantifier dispatch. Log: `/tmp/taitl-quantifier-investigation-clean-install.log`.

#### Cause

[Invariant.java](../../../../src/main/java/com/taitl/existential/constraints/Invariant.java) adds bare `Exists` and `All`
expressions to the invariant. [IndexEvs.eventKey](../../../../src/main/java/com/taitl/ex/logic/configuration/indexes/actions/IndexEvs.java)
uses the expression's Java class as its dispatch key: `Exists<Cat>` or `All<Cat>`.
[SplitEvent](../../../../src/main/java/com/taitl/ex/logic/evaluation/events/split_events/SplitEvent.java) looked up only runtime
event keys such as `Create<Cat>`, `CU<Cat>`, and `Port<Cat>`. It never requests the expression keys. Consequently,
[ExecuteHandlers](../../../../src/main/java/com/taitl/ex/logic/evaluation/events/actions/ExecuteHandlers.java) never reached
the quantifier, although it supports expression evaluation. The event-bound workaround instead registers an
`OnCreate` handler under `Create<Cat>`, so dispatch finds it.

#### Proposed correction and acceptance

Give entity expressions a shared dispatch route that runtime lookup includes exactly once, preserving declaration order
and type matching. Specify the admitted event scope and transition endpoint before changing dispatch; do not dispatch
by inventing `Exists` or `All` business events. Verify create/update/transit/access/deletion behavior as admitted,
checkpoint/commit rejection, positive matches, conditional All, missing keys, and short/full type names. Add failing
end-to-end regression tests before the fix, then remove the example workaround where the agreed semantics permit it.
Check that previously skipped rules in other example contexts do not create unexpected failures. Evaluate lookup and
cache costs using the existing performance guidance.

Requirements: [All entity invariants](../../specifications/QuantifiersAndIndexes.spec.md#all-entity-invariants),
[Exists entity invariants](../../specifications/QuantifiersAndIndexes.spec.md#exists-entity-invariants), and
[Configuration rule indexing](../../specifications/QuantifiersAndIndexes.spec.md#configuration-rule-indexing).
