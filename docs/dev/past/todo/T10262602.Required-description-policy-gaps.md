# T10262602 Required-description Policy Gaps

## Defects and correction

EffectBuilder verified configuration mutability but did not transfer the current required-description flag to its
Effect. Undescribed effects therefore bypassed the option. It now refreshes the prospective policy like invariant
and intent builders; Effect.add checks before appending. The new Effect.requireDescriptions setter mirrors those rule
sets and does not revalidate earlier handlers.

Invariant quantifier paths forwarded missing text into constructors that deliberately reject an explicit null
description. This also broke no-description Exists overloads while the flag was disabled. Invariant now normalizes
optional text after checking its prospective policy, before constructing All/Exists. Standalone constructors retain
their explicit-null input contract, as required by existing AllTest coverage. Omission uses the corresponding overload;
no unrelated constructor validation is relaxed.

## Acceptance and evidence

UserCanRequireRuleDescriptions covers seven declaration kinds in context and transaction builders: ordinary checks,
intents, effects, All, Exists, managed All, and managed Exists. It checks missing/empty text, corrected declaration,
prospective enable/disable through an existing builder, no partial append, freeze, and five validation descriptions.
All 33 targeted cases pass. Root mvn clean install passes 638 tests; standalone consumer verify passes seven tests;
the reactor clean install passes all modules, with zero failures/errors/skips. Checkstyle has zero violations and
PMD passes. Final reactor JaCoCo has 7,068/9,245 lines (76.45%) and 2,152/2,992 branches (71.93%); existing zero
thresholds do not establish full-repository coverage closure. No disabled tests were found; Failsafe selects zero
integration cases, while acceptance runs in Surefire. Artifact hygiene and Markdown checks pass. See
[Sprint 09](../../project/sprints/Sprint09_V2IndexesAndOperationalCoverage.md#required-description-option-coverage).

No transaction execution path or shared cache is changed. This is declaration-time validation and optional-description
construction. Performance measurements are not rerun for this configuration correction or the presentation-unit change.
