### S02222601 Error metadata for public exceptions

Status: complete on 2026-10-27 for the finalized public-library semantic error scope.

#### Delivery history

Introduce a small, consistent error metadata surface for public exceptions (error id + troubleshooting link), so
end users can map failures to specific docs quickly and log parsing remains stable. Start with
com.taitl.existential.exceptions and use a helper (e.g., ExceptionMessage) to append metadata without repeating
string concatenation in each call site.

- Define a compact error id catalog in a dedicated constants class.
- Update public exception factories to include error id + troubleshooting link.
- Add a troubleshooting section per error id and keep links stable.

The selected rule-evaluation slice now follows the
[structured diagnostics design](../../design/EventsAndConstraints.design.md#structured-violation-diagnostics) and
[finalized delivery plan](../planning/P10262602.Sprint09-structured-diagnostics.plan.md). Rust-inspired structured
data
drives detailed multiline getMessage() output by default. Library codes have no EX- prefix and identify failure
categories; existing consumer descriptions identify rules. Separate caller IDs/metadata declaration APIs were dropped
to keep declarations lightweight. This evolves the initial message-suffix proposal. The rule-evaluation slice now has
Diagnostic/DiagnosticCode snapshots, declaration provenance, intent/callback
classification, and lazy default messages. Final evidence is linked from Sprint 09. Coverage beyond rule evaluation
remains open; this suggestion was not complete at that delivery.


The [transaction-state delivery](../planning/P10272601.Sprint09-transaction-state-diagnostics.plan.md)
extends the catalog to closed/rollback-only handles, disposed managed views and missing active IDs, preserving catch
types and cleanup. Other public failures still need settled contracts and direct evidence; this suggestion remained open
until operational closeout.


#### Closeout

Completed on 2026-10-27 under the [Sprint 09 closeout plan][closeout]. Library-generated semantic configuration,
lifecycle, memo, maintenance, cleanup and standalone evaluation failures now carry stable code/remedy/troubleshooting
metadata. Java state/argument catch types remain exact with readable metadata; library exception types expose
detached snapshots. Caller-created constructors, ordinary programmer preconditions, internal unsupported stubs and
arbitrary caller exceptions retain their existing behavior. These are explicit catalog boundaries, not a claim to
classify every Java Throwable. Sprint 09 records 759-root/seven-consumer verification, retained V1 behavior, actual
coverage and paired performance evidence. This item is complete for that finalized public-library semantic scope.
