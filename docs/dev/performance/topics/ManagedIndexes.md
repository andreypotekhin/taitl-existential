# Managed indexes

The [first baseline](../runs/20261026T062911Z.ManagedIndexes.md) records three fresh-JVM samples of 10,000–100,000
Night City entities, 100/500 additional checks, repeated reports, sparse and single-group joins, and explicit eager
maintenance. It separates phase costs, complete success/rejection/recovery, allocation, and deterministic release.

Folding reduces physical updates and multi-valued key extraction. Complete workflow timing does not consistently beat
explicit maintenance; automatic report routing/allocation remains a measured optimization target. No numerical gate
is established. The manual-control seed timing is not comparable to a complete validated workflow.
