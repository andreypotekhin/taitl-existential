Environment: Amazon Corretto OpenJDK 17.0.15, Maven 3.9.10, macOS 15.6.1, aarch64. Three independent Maven/Surefire
processes per scenario ran on the same host. These are initial comparison samples, not a numerical performance gate.

## Complete transaction workflows

Each run used 10,000 entities, 100 actual descriptors, 100 validation declarations, one warmup workflow, and three
measured workflows. Fixture/configuration setup occurred before timing. Success and recovery performed 1,000,000
validation callbacks per workflow; each process reported 8,000,000 callbacks including warmup and measured work.
Rejection ran the rejection event, asserted the expected violation, and explicitly rolled back. Every workflow closed
its transaction; each process closed the library instance. Values are nanoseconds per workflow.

| Workflow | Sample 1 | Sample 2 | Sample 3 | Median | Range |
| --- | ---: | ---: | ---: | ---: | ---: |
| Success | 73,397,791 | 67,862,375 | 64,006,083 | 67,862,375 | 64,006,083–73,397,791 |
| Rejection with rollback | 1,074,500 | 924,972 | 840,375 | 924,972 | 840,375–1,074,500 |
| Rejection and recovery | 78,456,041 | 65,986,527 | 64,310,569 | 65,986,527 | 64,310,569–78,456,041 |

Command, repeated in a fresh Maven process for each sample:

    mvn -q -f examples/night_city/pom.xml \
        -Dexec.mainClass=com.taitl.ex.examples.night_city.app.NightCityExecutionBenchmark \
        -Dbenchmark.entities=10000 -Dbenchmark.types=100 -Dbenchmark.rules=100 \
        -Dbenchmark.warmup.iterations=1 -Dbenchmark.measure.iterations=3 compile exec:java

## Membership representation prototype

Each sample was a new Maven/Surefire process with 50 warmups and 500 measured repetitions. Each strategy constructed
all 20 rows from the same membership predicate, combined them, and enumerated the resulting sorted IDs. Set shapes
used 256 IDs: sparse (223 union IDs), broad (256), and clustered (184). Values are nanoseconds per operation.

| Shape | Representation | Sample 1 | Sample 2 | Sample 3 | Median | Range |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Sparse | Sorted arrays | 20,815 | 21,922 | 31,284 | 21,922 | 20,815–31,284 |
| Sparse | BitSet | 16,544 | 17,259 | 23,245 | 17,259 | 16,544–23,245 |
| Sparse | RoaringBitmap | 22,947 | 23,336 | 32,073 | 23,336 | 22,947–32,073 |
| Broad | Sorted arrays | 40,306 | 44,060 | 39,116 | 40,306 | 39,116–44,060 |
| Broad | BitSet | 26,410 | 27,987 | 37,827 | 27,987 | 26,410–37,827 |
| Broad | RoaringBitmap | 50,919 | 54,458 | 78,025 | 54,458 | 50,919–78,025 |
| Clustered | Sorted arrays | 39,073 | 41,186 | 50,744 | 41,186 | 39,073–50,744 |
| Clustered | BitSet | 22,977 | 19,973 | 27,021 | 22,977 | 19,973–27,021 |
| Clustered | RoaringBitmap | 26,002 | 27,050 | 38,343 | 27,050 | 26,002–38,343 |

Command, repeated in a fresh Maven process for each sample:

    mvn -q -Pbenchmarks -Dtest=MembershipRepresentationBenchmark \
        -Dbenchmark.warmup.iterations=50 -Dbenchmark.measure.iterations=500 test

BitSet was fastest in these compact-ID prototype samples. Variance is material, and the prototype does not yet model
EventField declaration ordering, actual handler selection, 100–500 rules, cache churn, allocation, or retained heap.
No production representation or dependency is selected from this result. RoaringBitmap remains test-scoped.
