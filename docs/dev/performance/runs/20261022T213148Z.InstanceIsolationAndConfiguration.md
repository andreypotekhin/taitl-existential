## Environment and workload

Amazon Corretto 17.0.15+6-LTS; Maven 3.9.10; macOS 15.6.1, arm64, Apple M4, 10 logical processors. Default JVM
options. Each setup workflow constructs one library, declares one exact operation context and one trivial invariant,
starts and commits its first transaction, and closes the library. Construction, config source loading, rule setup,
first begin, commit, and deterministic close are timed together. Warmup uses 50 fresh instances; measurement uses
250 fresh instances per JVM.

The steady transaction scenario constructs and configures one library and performs one untimed first transaction.
It then measures 2,500 empty begin/commit transactions after 500 warmup transactions. Library construction,
configuration, first begin, and final close are outside the timed interval. Scenarios run in setup-then-steady order.
Each workflow closes its instance; there are no entity events or growing source collections.

## Reproduction

From the repository root, each command below ran in a separate Maven/test JVM:

    mvn -q -Pbenchmarks -Dtest=InstanceConfigurationBenchmark -Dbenchmark.warmup.iterations=50 -Dbenchmark.measure.iterations=250 test

Three independent samples completed with zero failures. The benchmark profile selected the requested class.

## Summary and comparison

There is no matching prior measurement for this workload. The three samples establish a first local baseline and do
not define a performance gate. The setup workflow includes JVM object construction but excludes process/JVM startup.
The steady case uses empty transactions and does not represent event-heavy application traffic. The existing
[Night City workflow measurements][night-city] use different work and are not directly comparable.
