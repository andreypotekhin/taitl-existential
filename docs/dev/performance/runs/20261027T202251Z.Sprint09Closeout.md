## Method and exact assertions

From baseline and candidate in separate fresh JVMs, sample=1,2,3:

    mvn -q -Pbenchmarks -Dtest=Sprint09CloseoutBenchmark -Dbenchmark.sample=1 \
        -Dbenchmark.warmup.iterations=3 -Dbenchmark.measure.iterations=5 test

The first three pairs run baseline then candidate. Investigate initial success timing differences with three further
pairs (samples 4–6), using candidate-first, baseline-first, candidate-first ordering. Maven runs serially; no builds run
concurrently with measurement. All 12 JVM runs and 48 measured workflow rows pass. Each row averages five complete
workflows after three warmups; setup/initial configuration begin-close is printed separately. Library construction and
final library close are outside timing. Scenarios run in fixed order, so startup/JIT/GC and background activity affect
short samples. Medians/ranges are descriptive, not confidence intervals, latency percentiles or numerical gates.

SUCCESS is 1,000 begin/read/commit/dispose transactions and asserts exactly 1,000 checks. VALUES is 1,000 transactions,
each reporting a Cat plus a typed Command(cat, actor, destination) twice; identity folding yields exactly 2,000 checks.
MEMO_ERROR attempts 1,000 updates requiring absent memo, checks exact MemoException type, explicitly closes the handle,
then completes a fresh memo-backed update/read/commit. Each workflow asserts one effect and one check, released event
state and empty registry. Rendering=false never requests guard messages; true requests first and memoized messages
twice in total. The inference phase separately measures 100,000 shared cache hits per batch with a volatile sink after
three warmup batches; five measured batches are averaged. It is a metadata microbenchmark, not a transaction workflow.

Decimal MB = allocated bytes / 1,000,000. Allocation is positive/available for workflows and includes assertions and
harness overhead. It measures bytes created on the test thread, not retained heap or exclusive ownership. Zero-like
inference values include a fixed 58-byte measurement overhead per batch. Ownership/class-cache structure and close
isolation are tested deterministically; no GC or class-unloading deadline is inferred from timing.

## Interpretation and limits

Initial SUCCESS median is about 10% higher for the candidate and initial VALUES about 3% higher. The follow-up timing
ranges vary substantially for both variants and overlap; the respective median differences are about 7% and 24% in
that set, so a successful-path time cost remains possible and no stable speedup/regression magnitude is inferred.
The success path's only changed runtime lookup is ClassValue inference. Its isolated median hit time is similar in
the required samples, while allocation drops from 1.60 MB per 100,000 hits to measurement overhead. Startup/compilation
and callback/selection costs dominate these short complete workflows; source inspection finds no successful-path
snapshot construction or new payload ownership. The follow-up is retained rather than selecting the fastest samples.

Memo rejection deliberately costs more: unrendered candidate snapshots add approximately 0.5–0.7 MB per 1,000 attempts
in these samples; detailed first rendering plus reuse adds roughly 3.6–3.7 MB over the unrendered candidate. These buy
stable codes, escaped facts and targeted recovery while preserving stock catch types. No error-path speed improvement
is claimed. Reuse/description checks occur during declaration, not on each report. Existing managed-index cardinality
and maintenance records remain the evidence for unchanged index workloads.
