Each fresh process runs the five shapes below in fixed order. Entities are Cat objects; each location group has one
Dwelling. The reported rule count is additional successful create checks, alongside shared cat and dwelling rules.
Reports read all dwellings once and create every cat 1 or 16 times. Object identities remain distinct even when model
equality considers cats equal. Configuration, model construction, and one setup begin/close are outside measurement.
Each automatic fixture receives one successful complete warmup before phase profiling and measured workflows.
The eager fixture receives its own successful warmup before measurement. Each workflow is measured once per process;
three processes provide descriptive samples, not percentile statistics or a controlled JMH result.

Success includes begin, reports, validation and disposal. Rejection includes the expected rule failure, explicit
rollback,
and close. Recovery includes a rejection/rollback followed by a fresh successful transaction. Workflow assertions and
cleanup run inside those clocks; setup is excluded. Each checks the exact additional-rule invocation count despite
repeated reports. Manual-control only seeds a separate auto-disabled MultiIndex and closes; it omits events/validation
and is not a comparable complete workflow.

The paired eager-maintenance-success uses the same model/configuration rules and reports, but disables automatic join
maintenance and explicitly adds each side before reporting it. This forces per-report extractor/access work while
preserving validation behavior. It is a supported explicit-maintenance alternative, not the old standalone join
implementation, and does not claim identical reporting overhead.

## Phase and deterministic resource evidence

Phase clocks separate begin, reporting, first physical population, average warm query, 1,000 new pending identities,
next flush, and commit/disposal. Each new identity is reported the shape's repeat count. Warm-query values rounded to
0.0 µs reflect sub-0.05 µs averages; they do not mean zero work. Report allocation is separated from population.
The profile commits 1,000 additional cats beyond the shape's base entity count.

Before first population, exact assertions require zero physical updates and zero extractor calls on both multi-valued
join sides. First population performs one extraction and physical insertion per final identity. The next flush adds
exactly 1,000 left members, including in the large collision group. Repetition does not multiply these counters.

Live/closed storage is the instrumented graph rooted at the two ManagedMembership holders after incremental flush and
again after disposal. It excludes configuration, dispatch/event records, callback closures, DeferredIndexChanges,
view/access holders, and the complete Tr graph. Thus it is neither total retained transaction memory nor exclusive
retention. The closed graph is 2,336 bytes in every sample, with zero Cat/Dwelling objects; explicit side reference
counts are zero after disposal. Acceptance tests additionally retain views/handles and inspect pending/identity state.
No forced GC or weak-reference collection is used.

## Interpretation

- Shape 10000 / 100 / 1 / 100: automatic success median differs by +62.3% from eager success.
- Shape 10000 / 1 / 16 / 100: automatic success median differs by +31.2% from eager success.
- Shape 100000 / 1000 / 1 / 100: automatic success median differs by +4.5% from eager success.
- Shape 10000 / 100 / 1 / 500: automatic success median differs by +13.2% from eager success.
- Shape 100000 / 1 / 16 / 100: automatic success median differs by +42.4% from eager success.

Automatic folding establishes compact state and deferred extraction, but not a universal end-to-end speed advantage.
Per-report routing/signature/candidate allocation remains substantial, especially at 1.6 million reports. The eager
alternative bypasses automatic routing and can be faster despite repeated explicit additions. This supports keeping
the manual opt-out and identifies automatic report allocation as a future optimization target. Larger rule populations
also make validation dominate maintenance. Do not infer that either mode always wins from these short fixed-order runs.

The eager reference unit tests separately compare 2,000 randomized changes with queries every event, every seventh
event, and only at the end; timing samples do not establish replacement correctness. This session uses two model subject
types, rather than repeating the 20/100/200-type dispatch matrix already recorded under execution plans. It measures
managed maintenance cardinality/rules/collisions; read-policy opt-outs and early/failure combinations have acceptance
evidence rather than a separate timing matrix. No new universal speed, memory, or type-diversity claim is made.
