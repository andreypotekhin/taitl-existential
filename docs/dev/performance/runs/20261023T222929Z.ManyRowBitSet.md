## Why the earlier Night City fixtures missed the benefit

The [initial prototype](20261023T063904Z.ExecutionPlansAndTypeMatching.md) combined twenty membership rows per lookup.
Its 256-slot sparse case has 223 total memberships/223 union IDs; broad has 2,560/256; clustered has 640/184. The later
[compiled-selection comparison](20261023T215346Z.CompiledRuleSelections.md) groups declarations by event/type pattern.
At 256 rules, sparse and broad each select one row per descriptor; clustered selects a row for only 16 of 200
descriptors; overlapping averages 1.34 rows. Those labels no longer describe equivalent combination workloads. The
comparator also forced BitSet through an intermediate identifier array before final handler materialization. Neither
experiment alone settled the broader production choice. Historical records remain unchanged.

memo/bi-handler flags, and copy/immutability boundaries. RuleSelectionTest verifies a single compiled row is shared
across different dispatch signatures without suppressing per-entity execution.

## Ownership, methods, and reproduction

Production pattern bitmaps and precompiled selections are immutable by internal ownership after inventory publication.
Multirow resolution owns its accumulator; input bits are never mutated. Distinct matching patterns are collected once by
identity before union. Ascending declaration IDs preserve execution order and independent registrations. Memo admission
stays separate and per entity. No new end-user flag, strategy API, or external dependency is added; RoaringBitmap 1.6.8
remains test-scoped. Existing cache capacities, local generations, failure retry, and shutdown contracts remain intact
and are covered by retained tests.

Allocation uses current-thread ThreadMXBean. The graph agent sums shallow sizes over identity-deduplicated reachable
instance fields/arrays, excluding Class objects, static/ClassValue/JVM metadata, and weak referents. It measures
reachable holder storage rather than exclusive dominator retention or process heap. Retained callbacks are included;
fixture callbacks capture only counters. Entry budgets are not byte limits or proof of class-loader collection.

Native comparison, from the repository root after compiling test sources and attaching the graph agent:

    mvn -o -q -Pbenchmarks -Dtest=ManyRuleRowsBenchmark \
        -Dbenchmark.rules=256 -Dbenchmark.sample=1 \
        -Dbenchmark.warmup.millis=200 -Dbenchmark.measure.millis=300 \
        -Dbenchmark.heap.required=true test

Repeat sample=1,2,3 with rules=100,256,500. Grouped control adds -Dbenchmark.grouped=true at rules=256. Synthetic
control adds -Dbenchmark.synthetic=true at rules=256. Small-row controls add -Dbenchmark.small=true and assert 2/3
distinct rows. -Dbenchmark.rows can explicitly select a single cardinality. Do not substitute entity count for row
count; the row table log must prove the intended workload.

For the actual library probe, use java with -cp consisting of the chosen library JAR, target/test-classes, and AspectJ
runtime/weaver 1.9.21, plus the graph-agent/heap options above:

    java -cp "$PROBE_CLASSPATH" -Dbenchmark.rows=20 -Dbenchmark.rules=256 \
        -Dbenchmark.heap.required=true com.taitl.existential.benchmarks.DwellingSelectionProbe

Use rows=1,20,32, three fresh processes for each library, and alternate candidate order. Repeated adds
-Dbenchmark.reports=16 at rows=20. The Look control uses the same classpath without the agent and main class
com.taitl.ex.examples.night_city.app.NightCityExecutionBenchmark with entities=10000/types=200/rules=100 and
warmup.iterations=2/measure.iterations=5. The source companion identifies the committed baseline and measured JAR; a
historical dirty native-experiment snapshot requires its matching sources, not only the checkout SHA.
