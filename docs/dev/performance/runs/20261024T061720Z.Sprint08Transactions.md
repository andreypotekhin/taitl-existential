## Environment and workload

Amazon Corretto OpenJDK 17.0.15+6-LTS; Apache Maven 3.9.10; macOS 15.6.1, Apple Silicon arm64. Processor model,
core count, and active JVM options were not recorded. Concurrency is one. Each scenario warms up for 5,000 workflows,
then measures 50,000 workflows. In every full transaction workflow, begin/update/commit are timed; configuration is
outside the timed region. The custom-preparation scenario times creation of a per-iteration transaction with a
capturing effect, begin, and handle close; it does not report events. No-op dispatch reports a Cat update while its
only configured rule is for String. Empty-handler dispatch selects an empty Cat effect. Static/configured/custom
transaction scenarios execute an atomic counter effect. Scenario order is fixed within each test JVM. Each scenario
closes its Existential in try-with-resources; the preparation scenario also closes every handle.

## Reproduction

Each command ran in a separate Maven test JVM and exited zero. The benchmark profile ran only
`CustomTransactionBenchmark` (one test, no skips per sample).

```sh
mvn -q -Pbenchmarks -Dtest=CustomTransactionBenchmark -Dbenchmark.sample=1 -Dbenchmark.warmup.iterations=5000 -Dbenchmark.measure.iterations=50000 test
mvn -q -Pbenchmarks -Dtest=CustomTransactionBenchmark -Dbenchmark.sample=2 -Dbenchmark.warmup.iterations=5000 -Dbenchmark.measure.iterations=50000 test
mvn -q -Pbenchmarks -Dtest=CustomTransactionBenchmark -Dbenchmark.sample=3 -Dbenchmark.warmup.iterations=5000 -Dbenchmark.measure.iterations=50000 test
```

## Summary and comparison

No matching baseline exists for the added dispatch and preparation scenarios. The earlier
[custom transaction baseline](20261021T005604Z.CustomTransactions.md) uses a prior three-scenario harness, so these
results do not support before/after claims. The measurements confirm each path is independently exercised and
provide a baseline for later matching runs. They are descriptive averages, not latency percentiles or a performance
gate. A first setup attempt exposed that an empty configured context is invalid; the no-op and preparation cases now
configure an unmatched String invariant so they measure a valid context without invoking a callback on Cat events.
