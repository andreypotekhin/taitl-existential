# V1: Representative Core

Status: complete; local artifact installed as 0.0.1 on 2026-10-22; not published remotely. Target label: 0.0.1.
Dates/capacity: unassigned.
This charter replaces the initial subsystem-based split; see [rebaseline](ReleaseRebaseline.md).

## User outcome

Use a complete representative Night City workflow with robust success/rejection/recovery behavior, basic relationships
and evolution, and measured transaction-path costs. Consume the library through Night City's independent Maven project.

## Admitted scope

- Ordinary programmatic rules in one exact operation context; no dependence on unresolved wildcard ordering.
- Reported entity events, commit validation, explicit rollback/recovery, and deterministic resource release.
- A representative All/Exists relationship on caller-supplied collections and an explicit before/after evolution rule.
- Useful rule/operation errors, actual coverage evidence, bounded resource checks, and performance/scaling records.
- Night City has its own Maven POM and consumes the installed artifact without root source/test classpath inputs.

## Design and quality obligations

Correctness, actionable errors, failure recovery, resource hygiene, and performance must be addressed in each capability
design and its acceptance evidence. Robustness and performance take priority over minimizing release boundaries or
hardening cycles. These obligations apply to all three releases, not a late quality/performance phase.

Design readiness and implementation verification are recorded independently in [traceability](TraceabilityMatrix.md).
Finalize each selected capability's decisions and acceptance cases before its implementation. Broader unresolved
questions need not block independent ready work. Preserve existing tests and implementation outside this release's
claim.

## Non-goals

Independent instances, optional configuration sources, wildcard/generic breadth, advanced stages/intents/effects,
maintained relationship indexes, custom events, and external publication.

## Exit criteria

- All V1 capability acceptance cases, including negative/failure paths, pass with direct requirement links.
- The five quality design obligations have evidence; disabled report tests and missing coverage data are resolved.
- A clean library installation and independent Night City verification succeed; artifacts exclude example/test classes.
- Comparable workload/scaling and resource evidence is reviewed, with no unresolved release blocker.

## Release evidence

V1's locally installed 0.0.1 artifact was built on Amazon Corretto 17.0.15 with Maven 3.9.10 on macOS 15.6.1 arm64.
The recorded Git base was `397d52f061d6a5edaebed9b78418855599abf475`; the release verification included the closeout
working-tree changes.
The clean root build passes 455 tests with zero failures/errors/skips; JaCoCo execution data covers 234 classes and
checks pass, as do Checkstyle and PMD. Independent Night City verification passes 1 test and the separate reactor
builds all three projects. Both library JARs omit examples and tests; the dependency tree keeps JUnit test-scoped.
Three fresh workflow samples are recorded in [performance evidence](../performance/runs/20261022T205600Z.NightCityV1Closeout.md).
The build targets Java 11 bytecode, but runtime verification was performed on Java 17 only. External publication and
broader runtime compatibility remain unclaimed.
