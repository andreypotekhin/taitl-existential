# V2: Broader Standard Usage

Status: planned; not released. Target label: 0.0.2. Dates/capacity: unassigned.
This charter replaces the initial subsystem-based split; see [rebaseline](ReleaseRebaseline.md).

## User outcome

Apply the standard model across independently configured instances, richer context/type matching, transaction/stage
patterns, and maintained relationships while retaining V1 robustness and performance.

## Admitted scope

- Instance isolation, configuration sources/flags/freezing, and explicitly admitted concurrency/runtime behavior.
- Parent/wildcard/context-factory ordering and broader generic/subclass matching.
- Built-in stages, access events, intents/effects, custom transaction configuration, and their failure behavior.
- Maintained indexes/joins, fuller quantifiers, rich diagnostics, caching/global cleanup.
- Publication readiness is separate from functional completion; do not claim remote availability from a local build.

## Design and quality obligations

Correctness, actionable errors, failure recovery, resource hygiene, and performance must be addressed in each capability
design and its acceptance evidence. Robustness and performance take priority over minimizing release boundaries or
hardening cycles. These obligations apply to all three releases, not a late quality/performance phase.

Design readiness and implementation verification are recorded independently in [traceability](TraceabilityMatrix.md).
Finalize each selected capability's decisions and acceptance cases before its implementation. Broader unresolved
questions need not block independent ready work. Preserve existing tests and implementation outside this release's
claim.

## Non-goals

Custom event registration/splitting and unapproved strategy, hot-reload, dashboard, or plugin frameworks.

## Exit criteria

- V2 admitted combinations and retained V1 workflow/consumer cases pass with direct evidence.
- All five design obligations cover configuration, matching, callbacks, indexes, and lifecycle variations.
- Actual coverage, artifacts, dependency/runtime claims, resource results, and benchmark comparisons are reviewed.
- No release blocker remains; distribution claims match actual verified availability.

## Release evidence

Pending. Record the revision/dirty state, exact commands, runtime/tool versions, passed/skipped totals, actual coverage
and required checks, five quality obligations, consumer/artifact results, performance/resource records, blockers,
