# V3: Extensibility

Status: planned; not released. Target label: 0.0.3. Dates/capacity: unassigned.
This charter replaces the initial subsystem-based split; see [rebaseline](ReleaseRebaseline.md).

## User outcome

Define and use custom events through the established transaction model with predictable matching, evaluation, recovery,
resource ownership, and measured overhead.

## Admitted scope

- Custom event identity, registration, collision rules, handler binding, ownership, and concurrency restrictions.
- Custom/derived event splitting, context/transaction matching, intents/stages, and evaluation failure behavior.
- Only extensions justified by these accepted custom-event requirements; retain all V1/V2 regressions and consumer use.

## Design and quality obligations

Correctness, actionable errors, failure recovery, resource hygiene, and performance must be addressed in each capability
design and its acceptance evidence. Robustness and performance take priority over minimizing release boundaries or
hardening cycles. These obligations apply to all three releases, not a late quality/performance phase.

Design readiness and implementation verification are recorded independently in [traceability](TraceabilityMatrix.md).
Finalize each selected capability's decisions and acceptance cases before its implementation. Broader unresolved
questions need not block independent ready work. Preserve existing tests and implementation outside this release's
claim.

## Non-goals

Unapproved extension families, distributed effect orchestration, or broad compatibility promises without evidence.

## Exit criteria

- All admitted custom-event cases and retained V1/V2 behavior have direct success/rejection/failure evidence.
- The five design obligations include extension callbacks, split expansion, retained resources, and overhead.
- Full verification, actual coverage, independent consumption, artifacts, and resource/benchmark reviews pass.
- No required evidence is missing and no release blocker remains.

## Release evidence

Pending. Record the revision/dirty state, exact commands, runtime/tool versions, passed/skipped totals, actual coverage
and required checks, five quality obligations, consumer/artifact results, performance/resource records, blockers,
approved deferrals, and the hardening plan's retrospective. A charter or old completion mark is not release evidence.
The earlier [assessment](Assessment.md) contains historical observations, not proof of this new release scope.
